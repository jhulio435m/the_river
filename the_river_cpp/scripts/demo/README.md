# Demo recordings (real screen captures)

These scripts record the short clips shown in the "Demo real" section of the
website (`site/media/`). Everything on screen is the real software running —
`the_river_server`, `the_river_admin` and two `the_river_client` GUI windows —
driven with simulated keystrokes and mouse clicks. Nothing is mocked up or
edited afterwards: the capture is only cropped to the windows and compressed.

| File | Purpose |
| --- | --- |
| `record_demo.sh` | Orchestrates everything: Xvfb, server, shim, accounts, clients, xdotool choreography, ffmpeg capture and encoding. Cleans up every process on exit (trap). |
| `socks_shim.py` | Minimal SOCKS5 proxy standing in for Tor: accepts the client's `CONNECT <x>.onion:80` and pipes it to the local server (same technique as `tests/e2e_client_tests.cpp`). `--delay` adds latency before the reply so the client's real "NEGOCIANDO TOR" screen is visible; payload is never touched. |
| `create_users.py` | Tiny protocol-v2 client (TRV1 frames + SCRAM-SHA-256, `docs/PROTOCOL_V2.md`): `create` logs in as admin and runs `/newuser`; `first-login` does the mandatory `[CHANGE2]` for an account. Used to prepare bob off camera. |
| `locate.py` | Reads a screenshot of bob's window to find the newest chat line and the first button of a dialog, so clicks don't depend on hard-coded line counts. |

## Requirements

- A build of the three binaries (the script can do it with `--build`; default
  build dir `/tmp/demo_build`, override with `BUILD_DIR`).
- Linux with: `Xvfb`, `xdotool`, `xclip`, `ffmpeg` (libx264 + libvpx-vp9), `xterm`,
  `script` (util-linux), `zenity` (the client's Linux file picker), `python3`
  with Pillow, and a monospace font (DejaVu Sans Mono, `fonts-dejavu-core`).
  On Debian/Ubuntu:

  ```bash
  sudo apt-get install -y xvfb xdotool xclip ffmpeg xterm zenity fonts-dejavu-core python3-pil
  ```

- OpenGL via Mesa (the script sets `LIBGL_ALWAYS_SOFTWARE=1`, llvmpipe).

No Tor, network access or real secrets are needed.

## Usage

```bash
cd the_river_cpp
scripts/demo/record_demo.sh --build          # build, record, write site/media/*
scripts/demo/record_demo.sh --out /tmp/clips # write elsewhere
scripts/demo/record_demo.sh --keep-work      # keep raw captures, logs and DBs
```

Environment knobs: `DISPLAY_NUM` (default `:77`), `TYPE_DELAY` ms per typed
character (default 75), `SHIM_DELAY` seconds of simulated circuit latency
(default 2.0). A run takes about 3–4 minutes; failures stop the script (it
prints which step failed) and still clean up.

## What a run does

1. Starts Xvfb (1920x1080), a fresh `the_river_server` in a temp dir with a
   random 40-char `THE_RIVER_AES_KEY` (never printed or shown), a demo admin
   bootstrap password and no `THE_RIVER_NEW_USER_PASSWORD` (so `/newuser`
   produces a random one-time key), and the SOCKS5 shim. Clients get
   `THE_RIVER_ONION=<dummy 56-char>.onion` and `THE_RIVER_TOR_PROXY_PORT=<shim>`
   (with a non-default proxy port the client does not try to start Tor).
2. Creates bob's account and completes its first login with `create_users.py`
   (off camera). Each client runs in its own working directory and `HOME`, with
   a fixed `THE_RIVER_MACHINE_ID`, so the HWID binding is consistent.
3. Records, in order:
   - `admin` — `the_river_admin` in xterm: login, `/newuser` (alice's account
     and its one-time key), `/accounts`.
   - `login` — alice's client: connection screen, ES button, login with the
     one-time key read from the admin console output, first-access change to
     `alice`, first message.
   - `chat` — two 800x620 windows side by side: room messages, `Tab`
     nickname completion, `Up` history recall and edit.
   - `private` — `/fingerprint bob` and `/fingerprint`, `/msg bob ...`, `/r ...`.
   - `attachment` — alice: Attach → zenity (path pasted into the location entry) → `rio.png` (a Mandelbrot image
     generated by ffmpeg); bob: double-click the `[IMG]` line → Previsualizar.
   Between clips both clients run `/ping` and `/clear` off camera so every clip
   starts with an empty feed.
4. Encodes each capture to H.264 MP4 (CRF 28, yuv420p, 30 fps, faststart),
   VP9 WebM and a JPEG poster taken ~1 s before the end.

## Things the recordings show as they are

- On Linux the client drops its link when the attachment file picker is
  opened and reconnects by itself a few seconds later ("alice salió / alice se
  unió", "Enlace restablecido", history replay). It is visible in
  `attachment.mp4` and is left in on purpose.
- The connection screen's block characters (U+2588) are not in the glyph
  range the Linux client loads, so the animated background shows `?` marks.
- Some status details on the first-access screen are in English even with
  the Spanish UI ("First access detected...").
